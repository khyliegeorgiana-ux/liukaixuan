# Personal Portfolio Homepage Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the responsive homepage for Liu Kaixuan's public AI art and video editing portfolio.

**Architecture:** Create a dependency-free static page with semantic HTML, a shared CSS design system, and a small JavaScript module for mobile navigation and reveal effects. Placeholder links will point toward the approved future pages so the homepage can be reviewed before those pages are built.

**Tech Stack:** HTML5, CSS3, vanilla JavaScript, Python standard-library validation tests

**Spec:** `docs/superpowers/specs/2026-10-07-personal-portfolio-design.md`

## Global Constraints

- Use warm white, low-saturation light blue, and dark gray as the core palette.
- The design must feel refined and concise without large empty areas.
- Use decorative gradients, fine grids, soft glows, cards, tags, and numbering with restraint.
- Show “刘凯旋” in the hero, but not as text in the navigation brand area.
- Position the profile as “AI 美工 / 视频剪辑师”; do not mention graphic design.
- Support desktop and mobile layouts, keyboard navigation, readable contrast, and reduced-motion preferences.
- Keep the site dependency-free and suitable for static hosting.

## Review Focus

- At narrow mobile widths, navigation must collapse without horizontal overflow; Task 2 verifies the media-query and menu hooks.
- With JavaScript unavailable, primary page content and navigation links must remain readable; Task 1 verifies semantic links and content.
- Reduced-motion users must not receive reveal or scrolling animation; Task 2 verifies the corresponding media rule.
- Placeholder destination pages do not exist yet, so homepage review must use predictable relative URLs that later tasks can implement; Task 1 verifies all four destination paths.
- Contact calls to action must lead to the resume contact section rather than a separate contact page; Task 1 verifies `resume.html#contact`.
